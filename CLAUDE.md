# CLAUDE.md — zbrain

## Project

zbrain is a personal-Notion-for-agents: a typed, semantic, lineage-aware second brain exposed via the Model Context Protocol (MCP). It lives at the intersection of OpenClaw (the user's primary orchestrator), Claude Code, and any other MCP-speaking agent host.

**Authoritative design doc:** `~/.gstack/projects/zbrain/jackchen-no-branch-design-20260426-105721.md`
**Authoritative test plan:** `~/.gstack/projects/zbrain/jackchen-no-branch-eng-review-test-plan-20260426-105721.md`

Read the design doc before making any architectural decision. It is the source of truth for: storage schema, MCP tool contract, lineage validation, dream pipeline, OpenClaw integration, and the file watcher bridge.

## Stack (locked, post-Spike-A 2026-04-26)

- **Runtime:** Bun ≥ 1.3
- **SQLite client:** `bun:sqlite` — better-sqlite3 confirmed incompatible with Bun (issue #4290).
- **System sqlite:** `brew install sqlite` is REQUIRED. Bun's bundled sqlite has SQLITE_OMIT_LOAD_EXTENSION enabled; macOS system sqlite same. The fix: `Database.setCustomSQLite("/usr/local/opt/sqlite/lib/libsqlite3.dylib")` (Intel/Rosetta) or `/opt/homebrew/opt/sqlite/lib/libsqlite3.dylib` (Apple Silicon) BEFORE opening any Database. Resolver: `brew --prefix sqlite` → `lib/libsqlite3.dylib`. Override via `ZBRAIN_SQLITE_LIB` env var.
- **Vector extension:** `sqlite-vec` v0.1.9+ via `Database.loadExtension()` (validated by `bun run spike:vec`)
- **Markdown body parser:** `marked`
- **Frontmatter:** `gray-matter`
- **MCP:** `@modelcontextprotocol/sdk`
- **Embedding model:** OpenAI `text-embedding-3-small` (1536 dims; stored per-row so model swap = reindex, not migration)
- **Dream LLM:** configurable via `ZBRAIN_DREAM_LLM` env (default `anthropic`, model `claude-sonnet-4-6`)
- **Token counter for dream budget:** `gpt-tokenizer` (soft cap ~80k tokens)
- **Test runner:** `bun test`

## Run / build / test

```bash
brew install sqlite          # one-time prereq (extension-loading-enabled libsqlite3)
bun install                  # install deps
bun run spike:vec            # Day 0: verify sqlite-vec loads on this machine
bun run dev                  # run MCP server (development)
bun run bin/zbrain init      # scaffold the pages/ tree + identity.md + dream-prompt.md (once built)
bun run bin/zbrain dream     # one-shot dream consolidation (cron triggers this nightly via OpenClaw)
bun run bin/zbrain trace business/acme   # show spawn chain for a page (the demo flex)
bun test                     # full test suite
bun test:e2e                 # E2E only
bun run eval:dream           # dream prompt eval
```

## Hard architectural rules

1. **bun:sqlite, NOT better-sqlite3.** Do not mix runtimes.
2. **Disk first, SQLite second.** Inside any write tool: atomic-rename markdown → SQLite transaction → enqueue embedding. Crashes leave disk ahead of index; reindex's body_sha diff repairs the index from disk on next run.
3. **Lineage validation is server-enforced.** `agent_id` and `tool_call_id` are REQUIRED on every write. Server merges `orchestrator_session_id`, `parent_agent_id`, and `spawn_chain` from env vars (`ZBRAIN_ORCHESTRATOR_SESSION_ID`, etc.).
4. **No symlink / no shared filesystem with OpenClaw.** zbrain has its own `pages/` directory. The OpenClaw bridge is a one-way file watcher with sentinel lineage (`agent_id: "openclaw-watcher"`).
5. **Type field is advisory, NOT enforced.** No per-type tables. One `pages` table with freeform `frontmatter_json` blob.
6. **Page-addressed retrieval primary, semantic fallback.** Agent contract: prefer `get_page("slug")` when the slug is known; reach for `search_memory` only when the slug is not known.

## Skill routing

When the user's request matches an available skill, invoke it via the Skill tool. The skill has multi-step workflows, checklists, and quality gates that produce better results than an ad-hoc answer. When in doubt, invoke the skill. A false positive is cheaper than a false negative.

Key routing rules:
- Product ideas, "is this worth building", brainstorming → invoke /office-hours
- Strategy, scope, "think bigger", "what should we build" → invoke /plan-ceo-review
- Architecture, "does this design make sense" → invoke /plan-eng-review
- Design system, brand, "how should this look" → invoke /design-consultation
- Design review of a plan → invoke /plan-design-review
- Developer experience of a plan → invoke /plan-devex-review
- "Review everything", full review pipeline → invoke /autoplan
- Bugs, errors, "why is this broken", "wtf", "this doesn't work" → invoke /investigate
- Test the site, find bugs, "does this work" → invoke /qa (or /qa-only for report only)
- Code review, check the diff, "look at my changes" → invoke /review
- Visual polish, design audit, "this looks off" → invoke /design-review
- Developer experience audit, try onboarding → invoke /devex-review
- Ship, deploy, create a PR, "send it" → invoke /ship
- Merge + deploy + verify → invoke /land-and-deploy
- Configure deployment → invoke /setup-deploy
- Post-deploy monitoring → invoke /canary
- Update docs after shipping → invoke /document-release
- Weekly retro, "how'd we do" → invoke /retro
- Second opinion, codex review → invoke /codex
- Safety mode, careful mode, lock it down → invoke /careful or /guard
- Restrict edits to a directory → invoke /freeze or /unfreeze
- Upgrade gstack → invoke /gstack-upgrade
- Save progress, "save my work" → invoke /context-save
- Resume, restore, "where was I" → invoke /context-restore
- Security audit, OWASP, "is this secure" → invoke /cso
- Performance regression, page speed, benchmarks → invoke /benchmark
- Code quality dashboard → invoke /health

## Testing

Test framework: `bun test` (Bun's built-in runner; no extra deps). E2E tests spawn the MCP server in a subprocess and drive it via `@modelcontextprotocol/sdk` client.

## Prompt / LLM changes

The dream prompt at `pages/zbrain/dream-prompt.md` is the only LLM prompt under test. Any change to it MUST run `bun run eval:dream` against the eval fixtures and confirm entity/theme extraction doesn't regress ≥30%.

## OpenClaw deployment context

User's OpenClaw is cloud-deployed with a gateway routing to a local sandboxed Docker container that runs inference. v1 ships as standalone (`bun run`). v1.5 wraps in Docker for the actual deployment. See "Deployment Notes" + "OpenClaw-Specific Wiring" in the design doc.
